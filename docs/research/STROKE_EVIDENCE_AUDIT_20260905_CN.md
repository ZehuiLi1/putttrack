# 计杆证据审计（2026-09-05）

## 结论

现有数据足以证明小球的 50 Hz IMU 数据流保留了明显的击球/运动瞬态，但**不足以验证“正常击球”和“后续碰撞”的区分能力**。现在不能报告区分准确率，也不应把简单峰值阈值直接接入正式计杆。

本次审计比较了：

- 10 次干净、无遮挡的轻推；
- 10 次“推杆后撞固定边沿”；
- 另保留 1 次意外撞障碍的轻推作为混合样本，不纳入两组主比较。

21 段采集的 GO 后数据均无序列缺口，有效样本比例均为 100%。这说明数据完整性可用。两组每段都出现了大幅加速度瞬态，说明当前采样链路确实记录到了动作信号。

## 为什么目前不能区分

两组在所有被比较的描述特征上都有范围重叠：

| 特征 | 干净轻推范围 | 推杆后撞边范围 | 是否重叠 |
|---|---:|---:|---|
| BMI270 最大加速度模长 | 40.55–106.83 m/s² | 46.84–114.03 m/s² | 是 |
| 相邻样本加速度向量最大变化 | 41.85–116.84 m/s² | 52.47–123.72 m/s² | 是 |
| 最大角速度模长 | 32.62–52.09 rad/s | 37.33–60.46 rad/s | 是 |
| 陀螺仪削顶样本数 | 0–126 | 2–37 | 是 |
| ≥20 m/s² 候选脉冲簇 | 2–5 | 1–5 | 是 |
| ≥40 m/s² 候选脉冲簇 | 1–4 | 1–3 | 是 |

这里的“候选脉冲簇”只是相邻加速度向量变化超过阈值、且相隔不超过 0.16 秒的描述性聚类，并不代表真实球杆接触。干净轻推也经常产生多个候选簇，撞边样本有时只产生一个，所以数峰值会同时造成多计杆和漏计杆。

更关键的限制是：旧采集只记录了整个 episode 的操作说明，没有独立记录球杆触球和撞边的准确时间。由于每个撞边 episode 本身也包含一次真实推杆，无法把某个峰值归因给球杆或边沿，也就无法计算分类准确率。陀螺仪在不少 episode 中还发生削顶，进一步削弱了单靠峰值大小判断来源的可行性。

## 已落地的软件准备

运行以下命令可以从原始数据重新生成审计结果：

```bash
python3 tools/audit_stroke_evidence.py \
  experiments/research_ball_r1_pickup_precision_1d_gentle/manifest.json \
  experiments/research_ball_r1_pickup_precision_1e_rail/manifest.json \
  --output-dir docs/research/stroke_evidence_audit_20260905
```

输出包括：

- `stroke_evidence_audit_20260905/episode_features.csv`：逐 episode 特征；
- `stroke_evidence_audit_20260905/summary.json`：分组范围、重叠判断和证据限制；
- 所有输出都标记 `authority: false` 和 `INSUFFICIENT_TRUTH`，避免被误用为正式计杆验证。

此前准备的现场采集工具已经包含 0、1、2 杆场景，并支持审阅后填写实际杆数和相对 GO 的接触时间。下一轮现场工作应优先完成：单次轻推、停稳后第二杆、滚动中第二杆、一杆后多次撞边、其他球撞击以及手推滚动；碰撞场景还需单独记录碰撞时间。只有取得这些独立真值，才适合开发第一版离线计杆器并报告漏计、误计和 UNKNOWN。
