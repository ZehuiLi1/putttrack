# 单球单洞原型阶段收尾 — 2026-09-15

本阶段核心研发与现有台架验证基本完成，下一阶段是球内 PCB 固定、固定后短轮复测和大量真实击打实验。当前验收重点是放球可识别、实际推杆计数和单洞流程；人手拿放误触发暂不作为本阶段验收门槛。实验计杆不等于经过独立样本验证的量产分类器。

## 本阶段结果及计时边界

- 原版 Tag：用户约 100 次放球、约 99% 成功；自动日志为 100 次有效 NFC 后的身份核对全部完成，平均 1.56 秒、最长 1.93 秒。这不是独立测得的 99/100 物理放球率。
- XIAO：用户 50 次放球全部成功；自动日志 50/50 核对完成，平均 1.64 秒、最长 2.75 秒。自动计时从有效 NFC 开始，不含首次 NFC 前等待。
- 原版 Tag：自动开场至唤醒并核对 BLE 分别 3.205、3.204、3.559 秒；每轮唤醒后 5 秒 IMU 检查通过。
- XIAO：相同自动流程分别 2.629、2.732、2.629 秒；每轮 251 帧，检查通过。
- 自动休眠验证包含启动标识变化、NFC 唤醒标志、加密恢复及 IMU；它不是休眠电流测量，也不代替物理多姿态放球。
- 最新 XIAO 新规则现场局有 5 个候选、5 次 IMU 自动计杆、无手动补杆，1733 帧连续有效；用户报告其中一次体验有问题，具体事件未标注。总数一致不等于无漏记/重复记。
- PuttTrack 保存的入洞结算仍来自模拟按钮。Golf Up 光电无需从零验证，但它的真实事件接入本系统局号并完成结算仍属集成工作。

摘要证据：[收尾数据](reports/single_hole_closeout_20260915.json)。详细时间线见 [单洞记录](SINGLE_HOLE_BENCH.md)。原始本机 `runs/` 日志及固件二进制被 Git 忽略，保留在实验电脑，未随源码推送；已标注 XIAO 六杆回归采样保存在 `tests/fixtures/xiao_six_strokes.json`。汇总不代替原始数据。

## 现在可以继续自动完成的工作

- 用现有日志回放计杆、检查序号连续性和异常、按设备与规则版本汇总；已有工具和回归夹具。
- 固定后重复自动休眠唤醒、BLE/IMU 短轮健康检查；需要球处于已知固定位置和供电状态。
- 为每次大量击打采集保存设备、固件、计杆版本、安装版本和人工实际杆数；随后比较漏记、重复记与延迟。
- 实体灯型号/GPIO 和光电接入方式确定后，完成驱动与单洞事件联调。

本次没有再次切换射频场、给球休眠或改固件；收尾构建仅生成本地候选文件，不替换已确认镜像。

## PCB 固定后的实验顺序

1. 给安装状态编号（例如 `xiao-mount-v1`），记录 PCB、天线、电池位置及固定方式；保存照片。固定前后数据分组，不混作同一安装条件。
2. 装好后先检查有无松动与线缆受拉，保持当前电容配置；先少量击打确认固定仍可靠。
3. 先复测 20–30 次物理放球，以及 3 轮自动休眠唤醒和短时 IMU。观察放球体验，不以持续 NDEF 100% 为目标。
4. 再做轻推/正常推各一小组，逐杆标注实际次数，确认不会明显漏记或重复记后开始大样本。
5. 大样本按安装版本、力度、表面与球分组，预留不参与调参的新一组作为验证。优先评估真实击打，人手拿放另列后续范围。

